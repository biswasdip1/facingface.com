# WebRTC TURN relay references

## Why the relay is required

When both callers can exchange signaling but remain at “Connecting audio and video…”, the browser has not established a usable peer-media route. TURN provides a relay route when direct peer-to-peer WebRTC traffic is blocked by mobile carriers, NAT, firewalls, or restrictive Wi-Fi.

## Supported FacingFace configuration

FacingFace now supports a Metered TURN credential API from server-side environment values:

- `METERED_TURN_APP_NAME`
- `METERED_TURN_API_KEY`
- Optional: `METERED_TURN_REGION=global`

The server requests ICE entries and sends the browser only the returned STUN/TURN details. The API key does not enter the browser bundle.

It also supports any standards-compliant provider with:

- `WEBRTC_TURN_URLS` (comma-separated TURN/TURNS URLs)
- `WEBRTC_TURN_USERNAME`
- `WEBRTC_TURN_CREDENTIAL`

## Official references

1. Metered TURN API, “Get TURN Credential”: `https://www.metered.ca/docs/turn-rest-api/get-credential`.
   - Documents `GET https://<appname>.metered.live/api/v1/turn/credentials?apiKey=...` and a response with STUN/TURN URLs, username, and credential.
2. Metered TURN guide: `https://www.metered.ca/blog/guide-to-setting-up-your-webrtc-turn-server-with-metered/`.
   - Documents global TURN endpoints, TCP/TLS port 443 options, and a 5 GB/month free plan statement at time of reading.
3. Cloudflare Realtime TURN credential generation: `https://developers.cloudflare.com/realtime/turn/generate-credentials/`.
   - States that the long-term TURN key must remain server-side and that its API can generate short-lived browser ICE credentials.
4. Twilio Network Traversal Service: `https://www.twilio.com/docs/stun-turn/api`.
   - Documents short-lived ICE/TURN credentials generated by server-side API request.

The production release preserves the current STUN fallback if no relay environment values are configured, but fallback-only calls can remain blocked on some networks.
